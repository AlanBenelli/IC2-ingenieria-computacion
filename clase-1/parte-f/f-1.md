# Parte F — Git y GitHub (en equipo)

Esta guía reúne los pasos y comandos necesarios para realizar los ejercicios de Git y GitHub de la Clase 1.

Repositorio del equipo: `IC2-ingenieria-computacion`

## F1 — El ciclo completo

1. Clonar el repositorio:

   ```bash
   git clone https://github.com/AlanBenelli/IC2-ingenieria-computacion.git
   cd IC2-ingenieria-computacion
   ```

2. Crear el archivo `notas-equipo.md` con los nombres de los integrantes.

3. Agregar el archivo:

   ```bash
   git add notas-equipo.md
   ```

4. Crear un commit:

   ```bash
   git commit -m "Agrega integrantes del equipo"
   ```

5. Subir los cambios:

   ```bash
   git push origin main
   ```

6. El otro integrante debe actualizar su repositorio:

   ```bash
   git pull origin main
   ```

De esta manera, los cambios realizados aparecen también en la computadora del compañero.

## F2 — Mensajes que sirven

Realizar tres commits utilizando mensajes claros que describan los cambios.

Ejemplos:

```bash
git add .
git commit -m "Agrega archivo de integrantes"
```

```bash
git add .
git commit -m "Actualiza documentacion del proyecto"
```

```bash
git add .
git commit -m "Corrige errores en los ejercicios"
```

Para consultar el historial:

```bash
git log --oneline
```

Los mensajes deben permitir entender qué cambios se realizaron.

## F3 — .gitignore

1. Crear un entorno virtual:

   ```bash
   python -m venv .venv
   ```

2. Crear un archivo `.gitignore` en la raíz del repositorio.

3. Agregar las siguientes líneas:

   ```gitignore
   .venv/
   __pycache__/
   *.pyc
   .pytest_cache/
   ```

4. Comprobar el estado del repositorio:

   ```bash
   git status
   ```

Git dejará de mostrar los archivos y carpetas ignorados como cambios pendientes.

## F4 — Provocar un merge conflict

Este ejercicio requiere dos integrantes trabajando sobre el mismo repositorio.

1. Ambos integrantes deben actualizar sus repositorios con `git pull`.
2. Los dos deben modificar la misma línea de un archivo.
3. Cada uno debe guardar sus cambios mediante un commit.
4. El primer integrante realiza el `push`.
5. El segundo intenta realizar el `push` y Git lo rechaza porque el repositorio remoto tiene cambios nuevos.
6. El segundo integrante ejecuta:

   ```bash
   git pull --no-rebase
   ```

7. Git detecta el conflicto y muestra las secciones que deben resolverse.
8. Editar el archivo para elegir o combinar los cambios.
9. Marcar el conflicto como resuelto:

   ```bash
   git add .
   git commit -m "Resuelve conflicto de merge"
   git push origin main
   ```

## F5 — Volver atrás

1. Realizar un cambio que provoque un error.
2. Guardar ese cambio en un commit.
3. Consultar el historial:

   ```bash
   git log --oneline
   ```

4. Examinar los cambios de un commit:

   ```bash
   git show ID_DEL_COMMIT
   ```

5. Para revertir un commit sin reescribir el historial:

   ```bash
   git revert ID_DEL_COMMIT
   ```

Git crea un nuevo commit que deshace los cambios del anterior.

## F6 — Una rama propia

1. Crear una rama nueva:

   ```bash
   git checkout -b nombre-rama
   ```

2. Realizar un cambio en algún archivo.
3. Agregar y guardar los cambios:

   ```bash
   git add .
   git commit -m "Agrega cambios en nueva rama"
   ```

4. Volver a la rama principal:

   ```bash
   git checkout main
   ```

Los cambios realizados en la otra rama todavía no están incorporados en `main`.

## F7 — Traer la rama de vuelta

1. Asegurarse de estar en `main`:

   ```bash
   git checkout main
   ```

2. Unir la rama creada anteriormente:

   ```bash
   git merge nombre-rama
   ```

3. Subir los cambios:

   ```bash
   git push origin main
   ```

El contenido de la rama ahora forma parte de `main`.

## F8 — Guardar sin commitear (stash)

1. Comenzar a modificar un archivo sin realizar un commit.
2. Guardar temporalmente los cambios:

   ```bash
   git stash
   ```

3. Cambiar a otra rama:

   ```bash
   git checkout main
   ```

4. Volver a la rama donde se estaban realizando los cambios.
5. Recuperar los cambios guardados:

   ```bash
   git stash pop
   ```

Los cambios vuelven al directorio de trabajo y pueden continuar editándose.
